# 林嘉辉（组长）—— 模块功能分析

负责模块：`common`（公共工具）、`db`（数据库访问封装）、`main`（程序入口）
对应文件：`common.h/.c`、`db.h/.c`、`main.c`

---

## 一、模块总体职责

作为组长，负责系统的**地基与骨架**：

1. `common`：提供全系统共用的常量、安全输入函数、密码哈希、控制台/对齐工具。
2. `db`：封装 MySQL 的连接、断开、写操作、查询，并统一使用预处理语句防止 SQL 注入。
3. `main`：程序入口，按"连接数据库 → 加载数据 → 进入主菜单 → 释放资源"的顺序驱动整个系统。

## 二、common 模块

### 功能
- 定义业务常量（学号/姓名长度、每页条数 `PAGE_SIZE=20`、及格线 60、优秀线 85）和角色枚举 `Role`、登录上下文 `LoginUser`。
- 控制台工具：`console_init`（设置 UTF-8 代码页，解决中文乱码）、`clear_screen`、`pause_hint`。
- **安全输入**：`read_line`（整行读取并去换行）、`read_int` / `read_double`（范围校验，非法时循环重输）、`read_password`（不回显，退格可删）。
- 密码哈希：`password_hash`（djb2 算法）。
- 工具：`str_trim`（去首尾空白）、`is_blank`（判空）、`print_divider`（分隔线）。
- 中文对齐：`disp_width`（中文/全角算 2 列）、`print_pad`（按显示宽度补空格，解决中文列表错位）。

### 关键算法：djb2 密码哈希
```c
unsigned long long h = 5381ULL;
for (const char *p = plain; *p; ++p)
    h = ((h << 5) + h) + (unsigned char)(*p);   // 等价于 h = h*33 + 当前字符
sprintf(out, "%016llx", h);                     // 输出16位十六进制
```
- 特点：实现简单、散列分布较好；数据库中只存哈希值，不存明文密码。

## 三、db 模块

### 功能
- 维护一个全局连接 `g_conn`：`db_connect`（`mysql_init` + 设置 utf8mb4 + `mysql_real_connect`）、`db_disconnect`。
- 写操作：`db_exec`（预处理 + 绑定参数 + 执行，返回受影响行数）、`db_exec0`（无参数版）。
- 查询：`db_query`（预处理执行后，把结果统一转成字符串二维表 `DbResult{ n_rows, n_cols, char ***data }`）、`db_query0`、`db_result_free`。
- 绑定辅助：`bind_str` / `bind_long` / `bind_double`，内部先 `memset` 清零。

### 核心流程：预处理语句（防 SQL 注入）
`prepare_and_run` 内部依次执行：
1. `mysql_stmt_init` 初始化语句句柄；
2. `mysql_stmt_prepare` 预编译 SQL（SQL 中用 `?` 占位）；
3. `mysql_stmt_bind_param` 把外部输入通过 `MYSQL_BIND` 绑定到占位符；
4. `mysql_stmt_execute` 执行。

查询时再 `mysql_stmt_bind_result` 绑定结果列、`mysql_stmt_store_result` 缓存、循环 `mysql_stmt_fetch` 取行。

### 为什么能防 SQL 注入
外部数据**从不与 SQL 文本拼接**，而是作为参数单独发送，数据库会把它当作纯数据值，
即使输入含 `' OR 1=1` 等内容也不会被当作 SQL 执行。

### 连接配置（db.h）
```c
#define DB_HOST "127.0.0.1"
#define DB_USER "root"
#define DB_PASS "1234"
#define DB_NAME "score_db"
#define DB_PORT 3306
```

## 四、main 模块

`main.c` 是整个程序的总调度，执行顺序清晰：

```c
console_init();                       // 1. 控制台 UTF-8
if (db_connect() != 0) return 1;      // 2. 连接数据库（失败则提示排查并退出）
auth_init(); student_init(); course_init();  // 3. 加载 用户/学生/课程 到内存数据结构
menu_main_loop();                     // 4. 进入主菜单（登录/注册）
student_free(); course_free(); auth_free();   // 5. 释放内存
db_disconnect();                      // 6. 断开数据库
```

## 五、答辩可能被问到的问题

**Q1：为什么要把数据库访问单独封装成 db 模块？**
A：解耦业务与数据库，业务层只调用 `db_exec/db_query`，不直接接触 MySQL API；
同时统一在一处保证使用预处理语句，从根源防止 SQL 注入。

**Q2：预处理语句和直接拼接 SQL 有什么区别？**
A：拼接 SQL 会把用户输入混进 SQL 文本，存在注入风险且每次都要解析；
预处理先编译 SQL 模板、再绑定参数，既安全又可重复执行、效率更高。

**Q3：密码为什么要哈希？djb2 原理？**
A：避免明文存储，即使数据库泄露也无法直接得到密码。djb2 以 5381 为初值，
不断执行 `h = h*33 + 字符`，最后转成十六进制串。

**Q4：中文列表为什么会错位？怎么解决？**
A：一个中文字符在控制台占 2 个英文字符宽度，但 `strlen` 只算字节数。
`disp_width` 按 UTF-8 编码判断，中文计 2 列，`print_pad` 再补足空格实现对齐。

**Q5：数据库连接失败怎么办？**
A：程序会提示三步排查——启动 MySQL 服务、执行 schema.sql 建库、核对 db.h 中账号密码。
