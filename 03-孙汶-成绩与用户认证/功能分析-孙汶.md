# 孙汶 —— 模块功能分析

负责模块：`score`（成绩管理）、`auth`（用户与权限）
对应文件：`score.h/.c`、`auth.h/.c`

---

## 一、模块总体职责

负责系统的**核心业务**：

- `score`：成绩的录入、修改、删除、多条件查询、统计分析、标准竞赛排名。
- `auth`：用户注册、登录、改密、增删，以及角色权限控制。

## 二、score 模块

### 数据结构
```c
typedef struct {
    char student_id[LEN_ID];  char name[LEN_NAME];
    char class_name[LEN_CLASS];
    char course_id[LEN_ID];   char course_name[100];
    double score;  char semester[24];
} ScoreRec;

typedef struct SNode { ScoreRec rec; struct SNode *next; } SNode;  // 单向链表
typedef struct { ScoreRec *items; int n; } ScoreSet;              // 结果集(数组,便于排序)
```

### 核心函数
| 函数 | 功能 |
|---|---|
| `score_add` | 录入成绩：校验 0~100、学号/课程存在，INSERT，联合唯一防重复 |
| `score_update` | 修改成绩：UPDATE（按学号+课程号定位） |
| `score_delete` | 删除成绩：DELETE |
| `score_query` | 多条件组合查询（AND 语义，空串表示不限制） |
| `score_query_by_student` | 查某学生全部成绩（学生角色使用） |
| `score_quicksort` | 快速排序（可按成绩/学号、升序/降序） |
| `score_show_paged` | 排序后分页展示（每页 20 条，回车翻页） |
| `score_list_build/print/free` | 由结果集构造单向链表、遍历、释放 |
| `score_stat` | 统计：平均分、最高/最低、及格率、优秀率 |
| `score_rank` | 标准竞赛排名（同分同名次） |

### 关键算法 1：多条件动态查询
- 以 `WHERE 1=1` 起头，哪个条件非空就追加 ` AND 字段=?`，并同步把值加入绑定数组；
- **条件值全部通过 `MYSQL_BIND` 绑定**，不拼接用户输入，安全且灵活。

### 关键算法 2：快速排序
- 选中间元素为基准（pivot），用双指针 i、j 从两端向中间扫描；
- 按比较函数交换，再递归排序左右两部分；平均 O(n log n)。
- 比较规则：按成绩时，成绩相同再按学号比较；也可按学号。

### 关键算法 3：标准竞赛排名
```c
int rank = 0; double last = -1;
for (int i = 0; i < n; ++i) {
    if (i == 0 || r[i].score != last) { rank = i + 1; last = r[i].score; }
    // 成绩与上一名相同则沿用上一名次 → 两个第1名后直接是第3名
}
```

### 统计指标
平均分、最高分、最低分、及格率（≥60）、优秀率（≥85），均由查询结果实时计算。

### 链表的作用
查询结果先以数组承载（便于快速排序），排序后构造成单向链表顺序遍历，
体现"数组利于随机/排序、链表利于顺序访问"的特点。

## 三、auth 模块

### 数据结构
```c
typedef struct User {
    char username[LEN_USER]; char pwd_hash[LEN_HASH];
    Role role; char student_id[LEN_ID];
    struct User *next;                 // 哈希桶内链
} User;
static User *g_table[HASH_SIZE];      // HASH_SIZE=127 个桶
```

### 为什么用链地址法哈希表
- 登录需按用户名快速查找，哈希表平均 **O(1)**；
- 用链地址法处理冲突：同一桶的用户用链表串起来；
- 桶数取素数 127，让哈希分布更均匀。

### 核心函数
| 函数 | 功能 |
|---|---|
| `auth_init` | 从 user 表加载全部用户到哈希表 |
| `auth_find` | 哈希定位桶 → 链表查找用户 |
| `auth_login` | 校验用户名+密码哈希，成功写入登录上下文 |
| `auth_register` | 注册学生（重名返回 -1） |
| `auth_add_user` | 管理员新增用户 |
| `auth_change_password` | 改密：校验原密码、新密码不能与旧相同 |
| `auth_delete_user` | 删除用户（**内置 admin 不可删除**） |
| `auth_list_all` | 遍历输出全部用户 |
| `role_to_str / role_from_str` | 角色与字符串互转 |

### 哈希函数（djb2 后取模）
```c
h = 5381;
h = ((h<<5)+h) + 字符;     // h*33 + 字符
return h % HASH_SIZE;       // 定位桶
```

### 登录校验流程
1. `auth_find` 找到用户（不存在 → 失败）；
2. 把输入密码做 djb2 哈希，与库中 `pwd_hash` 比较（不一致 → 密码错误）；
3. 成功则把用户名、角色、绑定学号写入 `LoginUser`。

### 权限控制
- 角色分为管理员/教师/学生，登录后进入不同菜单；
- 学生角色绑定学号，只能查询本人成绩；
- 内置管理员 `admin` 受保护，无法删除。

## 四、答辩可能被问到的问题

**Q1：成绩查询如何支持任意条件组合？**
A：以 WHERE 1=1 为基础，按用户是否填写动态追加占位条件，并用绑定数组按顺序绑定，
实现"填几个条件就按几个查"，且不拼接输入、防止注入。

**Q2：快速排序的过程和复杂度？**
A：选基准、双指针分区、交换、递归。平均 O(n log n)、最坏 O(n²)；
取中间元素作基准可避免有序数据退化。

**Q3：什么是标准竞赛排名？**
A：同分同名次，名次不连续——如两个并列第 1，下一个是第 3。
实现上仅当成绩变化时才把名次更新为"下标+1"。

**Q4：用户为什么用哈希表？怎么处理冲突？**
A：登录按用户名查找，哈希表平均 O(1)。冲突用链地址法，同桶用户用链表连接，
桶数取素数 127 减少冲突。

**Q5：登录密码怎么验证？**
A：数据库只存 djb2 哈希值；登录时把输入密码哈希后与库中值比较，
不接触明文，更安全。

**Q6：权限隔离体现在哪里？**
A：不同角色进入不同菜单；学生绑定学号、只能查本人成绩；
管理员 admin 内置且不可删除，防止误删导致系统无法管理。
