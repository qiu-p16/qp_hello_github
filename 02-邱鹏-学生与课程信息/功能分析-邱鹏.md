# 邱鹏 —— 模块功能分析

负责模块：`student`（学生信息）、`course`（课程信息）
对应文件：`student.h/.c`、`course.h/.c`

---

## 一、模块总体职责

负责系统的**基础信息维护**：学生档案和课程信息的增、删、改、查。
这两类数据是成绩管理的前提（成绩通过学号、课程号外键关联）。

- 学生数据用**二叉搜索树（BST）**按学号组织；
- 课程数据用**动态顺序表**组织。

## 二、student 模块（二叉搜索树）

### 数据结构
```c
typedef struct {
    char student_id[LEN_ID];   // 学号（关键字）
    char name[LEN_NAME];       // 姓名
    char class_name[LEN_CLASS];// 班级
    char gender[4];            // 性别
    int  age;                  // 年龄
} Student;

typedef struct StuNode {
    Student data;
    struct StuNode *left, *right;   // 左右子树
} StuNode;
```

### 为什么选二叉搜索树
- 学号是字符串且天然可比较，BST 按学号满足"左小右大"；
- 查找/插入/删除平均 **O(log n)**；
- **中序遍历（左→根→右）得到的就是按学号升序的结果**，无需额外排序。

### 核心函数
| 函数 | 功能 |
|---|---|
| `student_init` | 从数据库查询全部学生，逐个插入 BST |
| `student_find` | 按学号查找，返回学生指针（登录、注册、成绩录入都依赖它） |
| `student_add` | 新增：先查重 → 写库 INSERT → 插入 BST |
| `student_update` | 修改：UPDATE 数据库 → 更新树节点 |
| `student_delete` | 删除：DELETE 数据库 → 删除 BST 节点 |
| `student_list_all` | 中序遍历输出全部学生 |
| `student_list_by_class` | 中序遍历并按班级过滤 |
| `student_count` | 返回学生总数 |

### BST 关键算法
- **插入** `bst_insert`：从根开始，按学号 `strcmp` 比较，小则递归左子树、大则右子树，遇到空位置就新建节点；学号相同返回重复。
- **删除** `bst_remove`（三种情况）：
  1. 叶子节点：直接删除；
  2. 只有一个孩子：用孩子顶替；
  3. 有两个孩子：用**右子树中最小的节点**（最左下）替换被删节点，再把那个最小节点删掉。
- **中序遍历** `bst_inorder`：左子树 → 处理当前节点 → 右子树，保证有序。

### 外键约束提示
删除学生时，如果该学生仍有成绩记录，数据库外键会阻止删除，
程序提示"该学生可能仍存在成绩记录，请先删除其成绩"。

## 三、course 模块（动态顺序表）

### 数据结构
```c
typedef struct {
    char course_id[LEN_ID];        // 课程号
    char course_name[100];         // 课程名
    float credit;                  // 学分
    char semester[24];             // 学期
} Course;
// 用动态数组 g_arr 存储，g_len 当前长度，g_cap 容量
```

### 为什么选顺序表
- 课程数量相对固定、不多，需要按下标随机访问；
- 结构简单、内存连续、遍历快。

### 核心函数
| 函数 | 功能 |
|---|---|
| `course_init` | 查询课程，按课程号排序后填入数组 |
| `course_find` | 按课程号查找（内部 `index_of` 线性查找） |
| `course_add` | 新增：查重 → INSERT → 容量不足时扩容再追加 |
| `course_update` | 修改：UPDATE → 更新数组元素 |
| `course_delete` | 删除：DELETE → 数组元素前移覆盖 |
| `course_list_all` | 遍历输出全部课程 |
| `course_count` | 返回课程数 |

### 动态扩容
`ensure_cap`：当需要的容量超过当前容量时，按 2 倍扩容（`realloc`），
初始容量 16，避免每加一门课就重新分配。

## 四、答辩可能被问到的问题

**Q1：学生为什么用二叉搜索树而不是数组？**
A：学生需要频繁按学号查找、且要求有序输出。BST 平均 O(log n) 查找，
中序遍历天然有序；数组查找/插入是 O(n)，数据量大时效率低。

**Q2：BST 删除有两个孩子的节点怎么处理？**
A：用右子树中最小的节点（即中序后继）替换它，再在右子树中删除那个最小节点，
这样既删了节点又保持 BST 性质。

**Q3：BST 最坏情况会怎样？**
A：若插入数据本身有序，会退化成链表，查找变 O(n)。本系统数据量小（一个班级），
且学号随机分布，实际接近平衡；改进方向可用 AVL/红黑树。

**Q4：课程为什么用顺序表？**
A：课程数量固定、很少，需要随机访问和简单遍历，顺序表实现简单、内存连续，
删除时用元素前移即可，完全够用。

**Q5：顺序表如何扩容？为什么用 2 倍？**
A：容量不足时 `realloc` 成 2 倍；2 倍扩容能保证插入操作的均摊 O(1)，
又不会浪费过多空间。

**Q6：删除学生/课程失败的原因？**
A：成绩表通过外键引用了学生和课程，只要还有成绩记录，数据库出于数据完整性会拒绝删除，
需要先删除相关成绩。
