## 二、为什么学生用 BST、课程用顺序表？

这是这个模块最值得讲的设计点：



|       | 学生 student                | 课程 course            |
| ----- | ------------------------- | -------------------- |
| 数据量   | 80 人，且以后会增加               | 只有 8 门，基本固定          |
| 主要操作  | 按**学号查 / 删 / 改**，要按学号有序输出 | 要遍历列表、按下标取           |
| 存储结构  | **二叉搜索树 BST**             | **动态顺序表 (数组)**       |
| 查找复杂度 | O(log n)                  | O (n)，但 n=8，无所谓      |
| 输出顺序  | 中序遍历 = 学号升序，天然有序          | 按 course\_id 排序后直接遍历 |

**答辩话术**：学生多、按学号关键字频繁查找，所以用 BST 把查找降到 O (log n)，中序遍历还能直接得到学号有序的列表；课程只有 8 门，数量小、变化少，用最简单的动态数组就够了，不必引入树的复杂度。

## 三、数据结构

### 1. Student（学生）



```
typedef struct {

&#x20;   char student\_id\[LEN\_ID];     // 学号（BST 的排序关键字）

&#x20;   char name\[LEN\_NAME];         // 姓名

&#x20;   char class\_name\[LEN\_CLASS];  // 班级

&#x20;   char gender\[4];              // 性别

&#x20;   int  age;                    // 年龄

} Student;

typedef struct StuNode {         // BST 节点

&#x20;   Student data;

&#x20;   struct StuNode \*left, \*right;

} StuNode;
```

全局只有一棵树根：`static StuNode *g_root`，一个计数器 `g_count`。

### 2. Course（课程）



```
typedef struct {

&#x20;   char course\_id\[LEN\_ID];

&#x20;   char course\_name\[100];

&#x20;   float credit;       // 学分

&#x20;   char semester\[24];   // 开课学期

} Course;
```

全局是一段动态数组：`g_arr`（数据）、`g_len`（当前数量）、`g_cap`（容量）。

## 四、学生模块（student.c）逐函数讲解

### 1. BST 内部操作（static，不对外暴露）



| 函数            | 作用          | 关键点                                  |
| ------------- | ----------- | ------------------------------------ |
| `bst_insert`  | 按学号大小插入     | 递归；遇到学号相同就把 `*ok=0`，用于**查重**         |
| `bst_search`  | 按学号查找       | `strcmp` 比大小，小走左、大走右，O (log n)       |
| `bst_min`     | 找最左节点（最小学号） | 删双子节点时用来找 "后继"                       |
| `bst_remove`  | 删除节点        | 单孩子直接接；**双子节点用右子树最小值顶替**（二叉搜索树标准删除法） |
| `bst_inorder` | 中序遍历输出      | 左→根→右 = 学号升序；可传 `filter_class` 只打印某班 |
| `bst_free`    | 后序遍历释放整棵树   | 防内存泄漏                                |

**删除演示（双子节点情况）**：



```
要删的节点有两个孩子 → 找右子树里最小的那个，把它的数据拷过来，

&#x20;                      再递归删掉那个最小节点。这样删完仍然是 BST。
```

### 2. 对外接口（和数据库联动）



| 函数                               | 做了什么                        | 数据库操作                                        |
| -------------------------------- | --------------------------- | -------------------------------------------- |
| `student_init`                   | 程序启动时，把整张 student 表读进来建 BST | `SELECT ... FROM student`                    |
| `student_add`                    | 先查重，再写库，成功后插入内存树            | `INSERT INTO student(...) VALUES(?,?,?,?,?)` |
| `student_update`                 | 按学号改姓名 / 班级 / 性别 / 年龄       | `UPDATE student SET ... WHERE student_id=?`  |
| `student_delete`                 | 按学号删；**删库成功后才删内存节点**        | `DELETE FROM student WHERE student_id=?`     |
| `student_list_all`               | 中序遍历打印全部                    | 无（读内存）                                       |
| `student_list_by_class`          | 中序遍历时按班级过滤                  | 无（读内存）                                       |
| `student_find` / `student_count` | 查单个学生 / 返回总数                | 无                                            |

### 3. 三个值得讲的细节

**① 全部用预处理语句（防 SQL 注入）**



```
MYSQL\_BIND p\[5];

bind\_str(\&p\[0], s->student\_id);

...

db\_exec("INSERT INTO student(...) VALUES(?,?,?,?,?)", p, 5);
```

用户输入不拼进 SQL 字符串，而是用 `?` 占位 + `bind` 绑定，从根本上杜绝注入。

**② 写库和改内存的顺序**

新增 / 修改：**先写数据库成功，再改内存树**。如果数据库报错（比如违反唯一约束），内存结构不动，保持一致。

**③ 外键约束的友好提示**



```
int n = db\_exec("DELETE FROM student WHERE student\_id=?", p, 1);

if (n <= 0) {

&#x20;   printf("删除失败：该学生可能仍存在成绩记录(外键约束)，请先删除其成绩。\n");

&#x20;   return -1;

}
```

因为 score 表外键引用了 student，只要这个学生还有成绩，数据库就拒绝删除 —— 代码捕获到失败后，给用户一句人话提示，而不是直接崩。

## 五、课程模块（course.c）逐函数讲解

### 1. 动态数组的扩容 `ensure_cap`



```
static void ensure\_cap(int need) {

&#x20;   if (need <= g\_cap) return;

&#x20;   int cap = g\_cap == 0 ? 16 : g\_cap;

&#x20;   while (cap < need) cap \*= 2;          // 容量翻倍

&#x20;   g\_arr = realloc(g\_arr, cap \* sizeof(Course));

&#x20;   g\_cap = cap;

}
```

和 `vector` 一样的思路：不够了就**翻倍扩容**，均摊 O (1)。

### 2. 接口一览



| 函数                | 作用                                       |
| ----------------- | ---------------------------------------- |
| `course_init`     | 启动时 `SELECT ... ORDER BY course_id` 读进数组 |
| `course_find`     | 线性查找课程号（只有 8 门，遍历完全够）                    |
| `course_add`      | 查重 → INSERT → 数组尾部追加                     |
| `course_update`   | UPDATE → 找到下标原地替换                        |
| `course_delete`   | DELETE → 找到后用后面元素前移覆盖（数组删除）              |
| `course_list_all` | 按下标顺序打印表格                                |

删除课程同样有外键提示："该课程下可能仍有成绩记录"。

## 六、一次 "新增学生" 的完整流程（答辩可以这么讲）



```
用户输入学号/姓名/班级...

&#x20;  │

&#x20;  ├─ 1. student\_find(学号) 查 BST，已存在 → 返回 -1"学号重复"

&#x20;  │

&#x20;  ├─ 2. 用预处理语句 INSERT 进 MySQL（带 ? 占位，防注入）

&#x20;  │       └─ 数据库返回 ≤0（失败/约束冲突）→ 返回 -2，内存不动

&#x20;  │

&#x20;  ├─ 3. 数据库成功 → bst\_insert 插入内存树，g\_count++

&#x20;  │

&#x20;  └─ 4. 返回 0 成功
```

## 七、答辩可能被问到的问题

**Q1：学生为什么用 BST 而不是数组？**

A：学生数据多、按学号查找频繁，BST 查找 O (log n)，中序遍历还能直接得到学号升序；课程只有 8 门，用数组更简单。

**Q2：为什么启动时要把数据库全部读进内存？**

A：减少每次查询都访问数据库的开销；日常列表展示、查找都走内存，增删改时才同步写库。

**Q3：怎么防止 SQL 注入？**

A：所有 SQL 都用 `?` 占位 + `MYSQL_BIND` 绑定参数，用户输入永远不拼进 SQL 文本。

**Q4：删学生失败是怎么回事？**

A：成绩表外键引用了学生，只要该学生还有成绩，数据库按参照完整性拒绝删除；程序捕获后提示先删成绩。

**Q5：BST 删除有两个孩子的节点怎么处理？**

A：用右子树最小节点（或左子树最大节点）顶替它的值，再递归删掉那个顶替节点，保持中序有序。

**Q6：内存数据和数据库会不会不一致？**

A：写操作遵循 "先写库成功、再改内存" 的顺序；任何一步失败都回滚内存修改，保证两边一致。
