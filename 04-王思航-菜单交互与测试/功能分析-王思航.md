# 王思航 —— 模块功能分析

负责模块：`menu`（菜单与交互层），以及**系统全面测试、文档编写整理**
对应文件：`menu.h/.c`

---

## 一、模块总体职责

1. `menu`：系统与用户交互的最外层，负责登录/注册入口、登录后按角色分流到不同菜单，
   并把各菜单项的输入采集后调用对应业务函数。
2. **系统测试**：对各功能模块进行黑盒测试，验证正常流程与异常输入。
3. **文档整理**：参与需求分析、详细设计、选题汇报等文档的编写与整理。

## 二、menu 模块

### 对外接口
```c
void menu_main_loop(void);   // 系统主循环：登录/注册入口，登录后进入对应角色菜单
```

### 内部组成
| 函数 | 功能 |
|---|---|
| `menu_main_loop` | 主菜单：1.登录 2.注册(学生) 0.退出 |
| `do_login` | 采集用户名/密码 → 调用 `auth_login` → 按角色分流 |
| `do_register` | 学生注册交互（用户名、两次密码、绑定学号） |
| `ask_str` | 读取字符串并去空白 |
| `change_my_password` | 修改密码交互（各角色通用） |
| `admin_menu` | 管理员菜单（学生/课程/成绩/用户全部功能） |
| `teacher_menu` | 教师菜单（录入、修改、查询、统计、排名） |
| `student_menu` | 学生菜单（查看本人成绩、排名、改个人信息、改密） |
| `student_manage` / `course_manage` | 学生 / 课程信息管理子菜单 |
| `query_scores` | 多条件成绩查询交互 |
| `input_score` | 成绩录入/修改交互 |
| `user_manage` | 用户管理子菜单 |

### 角色分流逻辑（核心）
```c
switch (u.role) {
    case ROLE_ADMIN:   admin_menu(&u);   break;
    case ROLE_TEACHER: teacher_menu(&u); break;
    case ROLE_STUDENT: student_menu(&u); break;
}
```
- 登录成功后根据角色进入不同菜单，菜单项数量、可执行操作不同，实现**权限隔离**。

### 菜单设计特点
- 所有菜单使用统一的"数字选择 + 循环 + 0 返回"模式，操作简单、可层层返回；
- 输入统一走 `read_int/read_double/ask_str`，非法输入会被拦截并提示重输；
- 菜单只负责"采集输入 + 调用业务函数 + 显示结果"，不直接操作数据库，职责清晰。

## 三、系统测试（本人负责）

### 测试方法
以**黑盒测试**为主，按功能点逐项验证；先测正常流程，再测边界与异常输入。

### 主要测试用例

| 编号 | 测试项 | 输入/操作 | 预期结果 |
|---|---|---|---|
| T1 | 管理员登录 | admin / 123456 | 登录成功，进入管理员菜单 |
| T2 | 错误密码 | admin / 错误密码 | 提示用户名或密码错误 |
| T3 | 学生列表 | 学生信息管理 → 全部学生 | 中序输出，按学号升序 |
| T4 | 新增学生 | 输入新学号等信息 | 新增成功；重复学号提示已存在 |
| T5 | 删除有成绩的学生 | 删除该学号 | 外键约束提示先删成绩 |
| T6 | 成绩录入 | 合法学号/课程/成绩 | 录入成功；重复录入提示联合唯一 |
| T7 | 成绩边界 | 成绩输入 -1 / 101 | 拦截并提示范围；输入 0、100 可接受 |
| T8 | 非法菜单选择 | 输入字母或超范围数字 | 提示无效并要求重输 |
| T9 | 多条件查询 | 只填班级/课程等 | 正确按条件过滤，分页正常 |
| T10 | 统计分析 | 对某课程统计 | 平均/最高/最低/及格率/优秀率正确 |
| T11 | 竞赛排名 | 含同分数据 | 同分同名次，名次正确 |
| T12 | 学生权限 | student1 登录 | 只能查看本人成绩，无录入/用户管理项 |
| T13 | 删除 admin | 用户管理删除 admin | 提示内置管理员不可删除 |
| T14 | 学生注册 | 绑定不存在的学号 | 提示学号不存在；正常则注册成功 |

### 测试结论
- 各模块正常流程功能正确，增删改查、统计、排名结果符合预期；
- 异常输入和边界值均有提示，不会导致程序崩溃；
- 权限隔离有效，学生无法越权操作。

## 五、答辩可能被问到的问题

**Q1：菜单层为什么要单独做一个模块？**
A：把交互逻辑和业务逻辑分开，菜单只负责采集输入、显示结果，业务函数可复用，
结构清晰、便于维护。

**Q2：不同角色的权限如何实现？**
A：登录后根据角色字段分流到不同菜单，学生菜单里根本没有录入、用户管理等入口，
学生查询也只按本人学号进行，实现权限隔离。

**Q3：你是怎么测试的？**
A：以黑盒测试为主，先正常流程后边界异常，针对每个功能点设计用例并核对预期结果，
重点验证了外键约束、联合唯一、成绩边界和权限隔离。

**Q4：发现过哪些问题？怎么处理的？**
A：例如中文列表错位（用显示宽度对齐解决）、删除有成绩的学生（外键拦截并提示）、
非法输入（统一校验重输），均已修复并回归验证。

**Q5：如果用户输入非法字符怎么办？**
A：所有输入都整行读取后用 strtol/strtod 解析并检查残余字符，
非法或超范围时循环提示重输，保证程序不会因错误输入崩溃。
